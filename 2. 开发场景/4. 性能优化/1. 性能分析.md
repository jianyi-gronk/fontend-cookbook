# 1. 性能分析

- 性能优化前，需要先分析性能，找到性能卡点，通常关注的是首屏渲染耗时，大致流程如下
  ```mermaid
  graph TD
    A[用户进入页面] --> B[请求获取静态资源]
    B --> C[浏览器加载资源]
    C --> D[请求获取业务资源]
    D --> E[浏览器加载业务模块]
    E --> F[核心业务模块渲染完成]
  ```
- 拆分成具体指标可以分为
  - 静态资源加载（ 离线包，CDN，体积优化 等 ）
  - 业务数据请求耗时（ 请求前置，SSE，数据裁剪 等 ）
  - 浏览器渲染耗时（ 懒加载，虚拟列表 等 ）

# 2. 性能指标

## 2.1 官方指标

- Google 推出了 Web Vitals，作为网页性能指标集，旨在简化和统一衡量网站质量的指标，其中最核心的部分，包含三个指标
  - LCP（ Largest Contentful Paint，加载性能 ）
    - 根据页面开始加载的时间到可视区域内可见的最大图像或文本块完成渲染的计算时间，用于测验加载性能，衡量网站初次载入速度，应该控制该值在 2.5 秒以内
    - 最大其实就是指元素的尺寸大小，这个大小不包括可视区域之外或者是被裁剪的不可见的溢出，也不包括元素的 Margin / Padding / Border 等
  - FID（ First Input Delay，测试交互性 ）
    - 首次输入延迟时间，主要为了测量页面加载期间响应度，测量交互性
    - 为了提供良好的用户体验，页面的 FID 应为 100 毫秒或更短，测量用户第一次与页面交互（ 单击链接、点按按钮等等 ）到浏览器对交互作出响应，并实际能够开始处理事件处理程序所经过的时间
    - FID 只关注不连续操作对应的输入事件，例如点击，轻触，按键等。一般只考虑测量首次输入的延迟。FID 只考虑事件处理过程的延迟，不考虑事件处理花费的时间或者事件处理完成更新页面花费的时间
  - CLS（ Cumulative Layout Shift，测试视觉稳定性 ）
    - 累积布局偏移，测量视觉稳定性。为了提供良好的用户体验，页面的 CLS 应保持在 0.1 或更少
    - CLS 即是测量整个页面生命周期内发生的所有意外布局偏移中最大一连串的布局偏移分数
    - 每当一个可见元素从一个已渲染帧变更到另一个已渲染帧时，就是发生了布局偏移。所谓一连串布局偏移，是指一个或者多个的布局偏移，这些偏移相隔少于 1 秒，总持续时间最大为 5 秒。而最大一连串就是所有的一连串布局偏移中偏移累计分数最大的一连串
- 除此之外还有其他比较常用的指标
  - TTFB（ Time to First Byte ）
    - 首包时间，资源请求到获取第一个字节之间的时间，包括以下阶段的总和
  - FCP（ First Contentful Paint ）
    - 首屏时间，首次内容绘制的时间，指页面从开始加载到页面内容的任何某一部分在屏幕上完成渲染的时间
  - FP（ First Paint ）
    - 白屏时间，首次渲染的时间点。FP 和 FCP 有点像，但 FP 一定先于 FCP 发生，例如一个页面加载时，第一个 dom 还没绘制完成，但是可能这时页面的背景颜色已经出来了，这时 FP 指标就被记录下来了。而 FCP 会在页面绘制完第一个 dom 内容后记录
  - SI（ Speed Index ）
    - 速度指数衡量页面加载期间内容的视觉显示速度，也就是页面填充快慢的指标。良好的 SI 应该控制在 3.4 以内
  - TTI（ Time to Interactive ）
    - 可交互时间，指标测量页面从开始加载到主要子资源完成渲染，并能够快速、可靠地响应用户输入所需的时间。良好的 TTI 应该控制在 5 秒以内。
  - TBT（ Total Blocking Time ）
    - 总阻塞时间，也就是从 FCP 到 TTI 之间的时间

## 2.2 自定义指标

- 通常不用官方指标，因为性能指标需要服务于业务场景，比如通常业务场景关注的是业务核心模块的渲染完成时间

# 3. 性能链路分析

## 3.1 各场景性能

- 通常使用 `performance.getEntriesByType()` 方法，用于 获取指定类型的性能条目（ PerformanceEntry ）列表，它返回一个数组，包含当前页面中所有满足该类型的性能数据
  ```js
  const entries = performance.getEntriesByType(type);
  ```

  - type：字符串，指定要获取的性能条目类型，常见取值有：
    - 'navigation'：页面导航相关时序（ 主文档加载 ）
    - 'resource'：所有请求（ 静态资源 包括 JS、CSS、图片、字体 等，以及业务请求 ）的加载时序
    - 'paint'：首次绘制（ FP ）和首次内容绘制（ FCP ）的时间点
    - 'mark'：自定义标记点，通过 `performance.mark()` 创建
    - 'measure'：自定义测量区间，通过 `performance.measure()` 创建
    - 'longtask'：长任务，超过 50ms 的任务
    - 'layout-shift'：布局偏移，用于 CLS 计算
    - 'first-input'：首次输入延迟，用于 FID

## 3.2 首屏性能分析

- 主要通过 performance.timing 或 PerformanceNavigationTiming 去获取页面加载时序，两者区别如下
  - 前者是以毫秒为单位，而后者是以微秒为单位
  - 前者记录时间戳，而后者记录与起始时间的时间差
  - 前端兼容所有现代浏览器以及 IE 9+，后者不支持 IE，支持 Chrome 60+，Firefox 58+，Safari 11+
  - 后者相比于前者，多提供 导航类型、重定向次数、协议 等信息
- 兼容低版本浏览器写法
  ```js
  const navigation = performance.getEntriesByType("navigation")[0];
  const timing = navigation || performance.timing; // 兼容旧版
  ```
- 核心属性
  - fetchStart：开始获取文档
  - domainLookupStart：开始 DNS 解析
  - domainLookupEnd：DNS 解析完成
  - connectStart：开始 TCP 握手
  - connectEnd：TCP 握手完成（ 含 TLS ）
  - requestStart：发送第一个字节
  - responseStart：收到第一个字节
  - responseEnd：收到最后一个字节
  - domContentLoadedEventEnd：DOM 解析完成（ 子资源可能未加载 ）
  - loadEventEnd：页面完全加载，所有资源加载完毕

## 3.3 请求耗时

- 首屏请求耗时
  ```js
  // 页面 load 后获取所有资源条目
  window.addEventListener("load", () => {
    const resources = performance.getEntriesByType("resource");
    resources.forEach((resource) => {
      // 处理每个资源的时序数据
    });
  });
  ```
- 非首屏请求耗时
  ```js
  const observer = new PerformanceObserver((list) => {
    list.getEntries().forEach((entry) => {
      if (entry.entryType === "resource") {
        // 埋点上报
        reportRequest({
          url: entry.name,
          duration: entry.duration,
          transferSize: entry.transferSize,
          ttfb: entry.responseStart - entry.requestStart,
          type: entry.initiatorType
        });
      }
    });
  });
  // 启动性能观察器，监听所有资源加载类型的性能条目
  observer.observe({ entryTypes: ["resource"] });
  ```
- 如果只想监控部分类型资源的请求耗时，可以通过 resource.initiatorType，常见值如下
  - 'img'：`<img>` 图片
  - 'link'：`<link>` 样式表、预连接等
  - 'script'：`<script>` 脚本
  - 'css'：CSS 文件中引用的资源，如 `background-image`
  - 'fetch'：`fetch()` API 发起的请求
  - 'xmlhttprequest'：`XMLHttpRequest` 发起的请求
