# 1. 离线包

## 1.1 基础使用

- 离线包 是将包括 HTML、JavaScript、CSS 等页面内静态资源打包到一个压缩包内，预先下载该离线包到本地，然后通过客户端打开，直接从本地加载离线包，从而最大程度地摆脱网络环境对 H5 页面的影响
- 每个离线包发布时，都会同步在 CDN 发布一个对应的线上版本，为了防止首次进入 app 还未下载离线包，CDN 目录结构和离线包结构一般相同
- 通常 CDN 地址会包含在离线包信息里，H5 容器会先截获静态资源请求，截获请求后，发生如下情况
  - 如果本地有资源可以满足该请求的话，H5 容器会使用本地资源
  - 如果没有可以满足请求的本地资源，H5 容器会使用线上资源

## 1.2 优化方案

- 上线 和 快速回滚
  - 可以引入新接口，用来告知客户端当前可以使用的版本白名单，客户端会 轮训，在每次冷启动 和在切后台返回时刷新接口数据（ 有较短时间的限频和缓存逻辑 ），从而可以实现以下能力
    - 发布新版本时，设置旧版本过期时间
      - 灵活控制旧版本的下线时间，如果在指定时间后，用户仍然没有更新到新版本，那么就会直接请求线上资源
      - 一般设置 2 个小时过期，就能保证大部分用户仍然可以享受到离线包的提速，也能保证不存在版本残留问题和更新不及时的问题
    - 快速下线
      - 在出现线上紧急 Bug 需要修复时，可以使用版本白名单，强制客户端走线上请求，但仍然保留本地离线资源包，从而方便后续发布新版本修复问题（ 增量发布 ）
- 虚拟域名
  - 通常需要通过 WebViewAssetLoader 创建虚拟域名（ 如 test:\/\/example.net ），将 assets 目录资源映射为网络路径，原因如下
    - 使用 file:// 协议会触发 CORS 限制
    - 防止用户看到了本地目录结构，存在安全风险
- 高低优先级
  - 离线包通常可以根据业务重要性设置不同优先级，比如让冷启动 App 的用户按照资源包优先级逐步下载到新版本
- 公共包
  - 集合公共 JS 资源，避免多份打包
- 增量包下发
  - 对每个版本的包，都会生成这个包和前 N 个版本差分计算的增量包，根据客户端当前离线包版本下载增量包
- 仅 wifi 下载
  - 节约用户流量
- 版本限制
  - 避免新资源包调用的客户端能力在旧版本不支持

# 2. 网络请求

- 启用 HTTP/2
  - 如果 HTML、CSS、JS 等资源都来自同一个域名，那么这些资源的请求可以全部复用同一个 TCP 连接，不需要为每个文件重新建立连接
- 使用 CDN 分发
  - 将静态资源部署到离用户最近的节点，降低 RTT（ 往返时延 ）
- 预操作
  - 预连接：在页面加载时，提前连接到静态资源的域名，避免在需要时才连接，导致延迟
    `<link rel="preconnect" href="https://api.example.com">`
  - 预解析：在页面加载时，提前解析静态资源的域名，避免在需要时才解析，导致延迟
    `<link rel="dns-prefetch" href="https://api.example.com">`
  - 预加载单个资源：以高优先级异步下载资源，但不会执行或应用
    ```html
    <link rel="preload" href="main.js" as="script" />
    <link rel="preload" href="style.css" as="style" />
    <link rel="preload" href="image.png" as="image" />
    ```
  - 预加载模块及其依赖树：会递归下载 app.js 中所有静态 import 的模块，适合 ES module 项目
    `<link rel="modulepreload" href="app.js">`
- 配置缓存策略
  - 强缓存
    - Cache-Control（ HTTP/1.1，推荐 ）
      - 常用指令
        - max-age=\<seconds\>：缓存有效期（ 相对请求时间 ），例如 Cache-Control: max-age=3600 表示 1 小时内直接使用缓存
        - no-cache：强制协商缓存（ 每次使用前向服务器验证 ）
        - no-store：禁止任何缓存（ 每次都要完整下载 ）
        - public / private：public 可被任何中间节点缓存（ 如 CDN ），private 只能被浏览器缓存
    - Expires（ HTTP/1.0，遗留 ）
      - 指定一个绝对过期时间（ GMT 格式 ），优先级低于 Cache-Control（ 若同时存在，Cache-Control 覆盖 Expires ）
  - 协商缓存
    - Last-Modified / If-Modified-Since
      - 服务器响应时返回 Last-Modified: 上次修改时间
      - 浏览器下次请求时带上 If-Modified-Since: 上次修改时间
      - 服务器比对：若资源未修改，返回 304；否则返回 200 和新资源
    - ETag / If-None-Match（ 更精确 ）
      - ETag 是资源唯一标识，通常是文件哈希
      - 浏览器下次请求时带上 If-None-Match: 旧ETag
      - 服务器比对：若一致则返回 304，否则返回 200 和新资源
      - 优先级高于 Last-Modified（ 因为 ETag 能解决时间精度不足、文件周期性修改等问题 ）
