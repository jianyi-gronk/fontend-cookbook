# 1. 考察事件循环

（从[这里](https://blog.csdn.net/yun_hou/article/details/88697954)看到的，感觉包含了很多，看这一个就够了）
（如果不会事件循环的，可以看看[这个](https://blog.csdn.net/m0_52212261/article/details/127747027?spm=1001.2014.3001.5502)）

1. 首先我们得了解 new Promise()和 promise.then()的执行
   （回调函数就是一个参数，将这个函数作为参数传到另一个函数里面，并且回调函数分同步回调和异步回调）
   new Promise 中的回调函数是同步回调，执行到该代码的时候，会直接放入执行栈内执行，promise.then()中的回调函数是异步回调，执行到该代码的时候，该异步回调不会直接执行，主线程继续向下执行，不会阻塞，等 promsie 状态确定后，该回调函数会被放入微任务队列
2. 其次我们得了解 async 和 await 的执行
   （async 和 await 的本质其实就是 Generator 和 Promise 的语法糖）
   关键字 await 会使 JavaScript 等待直到 promise 返回结果（await 后面的 new Promise()内的回调函数会被直接放入执行栈执行的），但它只是让 async 功能块等待，而不是整个主线程堵塞，所以主线程会跳过 await 下面的代码，继续执行，可以把它后面的一段代码当作是传入 promise.then()的回调函数，当 promise 的状态为成功时，就会被全部放入微任务队列
3. 最后是 setTimeout
   这个传入的回调放入宏任务队列，大伙应该都知道
4. 执行顺序
   先执行所有同步，之后执行异步微任务，再执行异步宏任务，大伙应该也都知道
5. 现在大伙们推推看

```
async function async1() {
  console.log('async1 start');
  await async2();
  console.log('asnyc1 end');
}
async function async2() {
  console.log('async2');
}
console.log('script start');
setTimeout(() => {
  console.log('setTimeOut');
}, 0);
async1();
new Promise(function (reslove) {
  console.log('promise1');
  reslove();
}).then(function () {
  console.log('promise2');
})
console.log('script end');

// 结果为：
// script start
// async1 start
// async2
// promise1
// script end
// asnyc1 end
// promise2
// setTimeOut
```

具体步骤：

1. 函数 async1，async2 被定义，但是没有调用，首先输出“script start”
2. setTimeout 中的的内容会被放到宏任务队列末尾
3. 调用函数 async1，输出 “async1 start”，执行函数 async2，输出 “async2”，await 下方的输出"async1 end"将会被放到微任务队列末尾
4. 执行 new Promise 的 executor 部分，输出 “promise1”，then 方法里的输出"promise2"被放到微任务队列末尾
5. 输出“script end”
6. 执行微任务队列中的代码，依次输出“async1 end”，“promise2”
7. 执行宏任务队列中的代码，输出“setTimeout”

（都不是直接放到任务队列里，只是这样好描述，就先这样描述，大伙懂就行）

# 2. 考察 this 指向

1. 基础样例（但是容易搞晕）

   ```
   function foo() {
       console.log(this.a)
   }
   function doFoo() {
       console.log(this.a)
       foo();
   }
   var obj = {
     a: 1,
       doFoo: doFoo
   };
   var a = 2
   obj.doFoo()

   // 结果为：
   // 1
   // 2
   ```

   this 指向函数的调用者，obj.doFoo()，所以 doFoo 内的 this 指向 obj，打印 1，然后调用 foo()，调用者为 window，所以 foo 内的 this 指向 window，打印 2

2. 关于 call，apply，bind（特殊情况，就看掌握的牢不牢固了，反正我翻车了）

   ```
   function a() {
     console.log(this)
   }
   a.call(null)

   // 结果为：
   // window
   ```

   如果 call，apply，bind 的第一个参数传入的是 null 或者 undefined，call 方法将把全局对象（浏览器上是 window 对象）作为 this 的值。所以，在浏览器上答案是输出 window 对象，要注意的是，在严格模式中，null 就是 null，undefined 就是 undefined

   ```
   'use strict'
   function a() {
       console.log(this)
   }
   a.call(null) // 打印null
   a.call(undefined) // 打印undefined
   function a(){
       console.log(this)
   }
   a.bind()() // 打印undefined
   function c(){
     a.bind()()
   }
   const d = { e: c }
   d.e() // 打印undefined
   ```

   （我上网搜，有一部分人说如果 bind 的第一个参数传入的是 null 或者 undefined，执行作用域的 this 将被视为新函数的 this，还有人说 this 不变，这都是错滴，验证了）

3. 关于 this 优先级

   ```
   function foo(something){
       this.a = something
   }
   var obj1 = {
     abc: function(){
       console.log(this)
     }
   }
   const d = new obj1.abc() // abc构造函数的实例化对象
   var bar = foo.bind(obj1)
   bar(2)
   console.log(obj1.a) // 2
   var baz = new bar(3)
   console.log(obj1.a) // 2
   console.log(baz.a) // 3
   ```

   this 绑定的优先级排序为，默认绑定 < 隐式绑定 < 显式绑定 < new 绑定 < 箭头函数
   （在网上搜 this 绑定优先级的时候，有一部分人说显示绑定和 new 绑定不能比较，因为 call 和 apply 不能和 new 绑定一起使用，但是 bind 可以和 new 绑定一起使用，所以还是可以比较的）
   1. 默认绑定，函数调用时无任何调用前缀的情景。非严格模式，默认绑定的 this 指向全局对象。严格模式，默认绑定的 this 指向 undefined
   2. 隐式绑定，哪个对象调用的函数，this 指向哪个对象，如果函数调用前存在多个对象，this 指向距离调用自己最近的对象， 即使那个对象没有那个属性
   3. 显示绑定，通过 call、apply 以及 bind 方法改变 this 的指向
   4. new 绑定，通过 new 操作符来调用函数时，会产生一个新对象，并且会把构造函数内的 this 绑定到这个对象上

4. 来个简单的

   ```
   var x = 3
   var y = 4
   var obj = {
       x: 1,
       y: 6,
       getX: function() {
           var x = 5
           return function() {
               return this.x
           }()
       },
       getY: function() {
           var y = 7
           return this.y
       }
   }
   console.log(obj.getX()) // 3
   console.log(obj.getY()) // 6
   ```

   假如函数 a，在函数 b 里面被 a()这样子调用，并不就是说 a 就是被 b 所隐式绑定调用，this 指向 b，而是说，a 前面没有前缀，所以就是默认绑定，指向 window

5. 关于箭头

   ```
   var obj = {
      say: function() {
        var f1 = () =>  {
          console.log("1111", this)
        }
        f1();
      },
      pro: {
        getPro:() =>  {
           console.log(this)
        }
      }
   }
   var o = obj.say
   o()
   obj.say()
   obj.pro.getPro()

   // 结果为：
   // 1111 window对象
   // 1111 obj对象
   // window对象
   ```

   箭头函数体内的 this 指向的是定义时上下文作用域的 this，而跟执行时没有关系，即一旦箭头函数的 this 绑定成功，也无法被再次修改，有点硬绑定的意思

# 3. 考察作用域，变量提升，函数提升，闭包

1. 基础样例

   ```
   (function(){
     var x = y = 1
   })()
   var z

   console.log(x) // Uncaught ReferenceError: x is not defined
   console.log(y) // 1
   console.log(z) // undefined
   ```

   （作用域分全局作用域和函数作用域，es6 多了 let 和 const，使用时会有个块级作用域）
   这个就挺基础的，x 在函数作用域范围内生效，所以在全局访问不到，报错，y 未声明直接赋值，相当于全局变量，所以可以得到它的值，z 声明但未赋值，所以为 undefined

2. 关于变量提升

   ```
   var name = 'World'
   (function() {
       if(typeof name === 'undefined'){
         var name = 'Jack';
         console.log('Goodbye ' + name)
      }else{
         console.log('Hello ' + name)
       }
   })()

   // 结果为：
   // Goodbye Jack
   ```

   只需要注意，变量提升即将变量声明提升到它所在作用域的最开始地方，而不是代码块的最开始地方即可，所以等效于

   ```
   var name = 'World!'
   (function () {
       var name;
       if (typeof name === 'undefined') {
           name = 'Jack';
           console.log('Goodbye ' + name)
       } else {
           console.log('Hello ' + name)
       }
   })();
   ```

3. 关于函数提升

   ```
   function Foo () {
       getName = function () {
       console.log(1);
       }
       return this;
   }
   var getName = function () {
       console.log(2);
   }
   function getName () {
       console.log(3);
   }

   getName();               // 2
   Foo().getName();         // 1
   ```

   1. getName()，下面的函数声明，会把函数提升到最前面（也是作用域最上面，也不是代码块最上面），但是上面函数表达式，相当于变量提升，只把变量提升了，然后后面把函数声明给覆盖了，所以最后执行的是函数表达式的，所以未 2
   2. Foo().getName()，调用 Foo()，getName 全局被重新赋值，并且返回 this 指向 window，所以后面的.getName()，执行的是全局的（即刚赋值的），所以为 1

4. 关于作用域链

   ```
   function a(){
       var temp = 10
       function b(){
           console.log(temp) // 10
       }
       b()
   }
   a()

   function c() {
       var temp = 10
       d()
   }
   function d(){
       console.log(temp) // 报错 Uncaught ReferenceError: temp is not defined
   }
   c()
   ```

   js 中变量的作用域链与定义时的环境有关，与执行时无关，执行环境只会改变 this、传递的参数等，即 a 中调用 b()的时候，会向上从 a 中招 temp，而 c 中调用 d()的时候，向上找就只能找到全局
   5. 来个恶心的 🤢

   ```
   function fun(n, o) {
       console.log(o)
       return {
         fun: function(m){
             return fun(m, n)
         }
       }
   }
   var a = fun(0);  a.fun(1);  a.fun(2);  a.fun(3);
   var b = fun(0).fun(1).fun(2).fun(3);
   var c = fun(0).fun(1);  c.fun(2);  c.fun(3);
   ```

   你说它难吧，还真不难，没涉及啥东西，你说它容易吧，我看半天才看懂这代码到底在干啥，注意它 return 后面的那个 fun(m, n)是调用外层的 fun，调用里面的 fun 是 this.fun()

# 4. 考察原型链

这个感觉挺简单的，随便看一个就行了

```
function Parent() {
    this.a = 1;
    this.b = [1, 2, this.a];
    this.c = { demo: 2 };
    this.show = function () {
        console.log(this.a , this.b , this.c.demo );
    }
    this.change = function () {
        this.b.push(this.a);
        this.a = this.b.length;
        this.c.demo = this.a++;
    }
}

function Child() {
    this.a = 2;
}

Child.prototype = new Parent()
var parent = new Parent()
var child1 = new Child()
var child2 = new Child()
child1.a = 11
child2.a = 12
parent.show()   // 1   [1,2,1]   2
child1.show()   // 11   [1,2,1]   2
child2.show()   // 12   [1,2,1]   2
child1.change()
child2.change()
parent.show()   // 1   [1,2,1]   2
child1.show()   // 5   [1,2,1,11,12]   5
child2.show()   // 6   [1,2,1,11,12]   5
```

需要注意的点：

1. 如果对象身上没有属性，则会在它所在的原型链上一层层往上找，找到就停，所以是取原型链上离对象最近的值
2. 如果调用对象身上的方法例 obj.fn()，其身上没有该属性，调用的是其原型链上其他对象的 fn()，这个 this 仍指向 obj，就比如 child1.change()调用的是 Parent 实例对象身上的方法，但是修改的 this.a 是 child1 身上的（隐式绑定）
3. 然后这里面还涉及到了一个原型链继承，就是子构造函数的原型对象指向父构造函数的实例化对象，不细说，这个简单
