# 1. 搜索引擎工作流程

- 搜索引擎工作流程，分为 4 个阶段
  - 发现：找出网络上存在哪些网页
  - 抓取与渲染：搜索引擎访问已发现的网址，获取页面具体内容
  - 索引编制：处理与分析已抓取网页的内容，并将其存入 Google 索引 数据库
  - 呈现搜索结果：用户查询时，机器在索引中搜索匹配项，依据数百个因素计算 相关性 并排序
- 搜索引擎录入是其中前 3 个阶段，是 SEO 的前提，只有在被收录的基础上才能获得关键词排名
- SEO 核心影响的是第四个阶段，但 SEO 的优化贯彻全部 4 个阶段

# 2. 搜索引擎录入

## 2.1 发现

- 背景
  - 因为不存在包含所有网页的中央注册表，因此 Google 必须不断搜索新网页和更新过的网页，并将其添加到已知网页列表中，此过程称为 “网址发现”
- 发现的主要途径
  - 链接追踪
    - 原理：Google 会定期重新访问已收录的网页，提取已知页面中指向新网址的链接
    - 场景：导航中心页（ 如分类目录、归档页 ）通常包含指向最新博文或产品外链，Google 通过爬取此类页面发现新内容
  - 站点地图提交
    - 原理：网站所有者在站长工具中提交 sitemap.xml 文件，直接提交给 Google
    - 作用：这个文件就像网站的 “目录”，清晰地列出了所有重要页面的网址及其更新频率，极大方便了搜索引擎蜘蛛的系统性抓取，帮助 Google 快速定位深层页面、孤岛页面或时效性较强的新发布内容
  - 网址检查工具
    - 原理：对于最重要的页面（ 如首页、核心产品页 ），可以使用站长工具提供的 “网址检查” 工具，直接提交单个 URL 请求索引
- 网址检查工具 和 站点地图 的区别
  - 网址检查工具
    - 本质是 针对单个 URL 的精确诊断与紧急推送
    - 可以主动请求抓取，google 针对该类型处理响应快，能快速发现并抓取
    - 通常在没有什么外链引用的情况，google 长时间没有发现主页面，可以通过该方式主动请求
  - 提交站点地图
    - 本质是 对整个网站结构的宏观告知与长期指引，帮助 google 快速理解网站结构
    - 通常在网页复杂的情况，方便 google 快速发现网站的子页面，比如子页面被漏抓取
- 发现失败的常见原因
  - 网站缺乏外部链接
    - 新网站如同孤岛，如果没有其他已被收录的网站链接到它，搜索引擎蜘蛛就很难发现它的存在
    - 但不要付费购买链接，这可能被视为违反搜索引擎的垃圾内容政策
  - 缺少网站地图
    - 子页面可能未被直接引用，导致搜索引擎无法发现它们
  - 网站刚刚上线
    - 搜索引擎发现和抓取新网站需要一定的时间，对于全新网站或现有网站的重大更新，这个过程可能需要几周
  - 偶然被遗漏
    - 尽管搜索引擎能抓取海量网页，但仍有可能偶然漏掉一些规模较小的新网站

## 2.2 抓取与渲染

- 定义
  - 抓取 指 Google 访问已发现的网址，下载页面内容（ 文本、图片、视频等 ）的过程，执行抓取任务的程序叫做 Googlebot（ 又称 蜘蛛、抓取工具 或 漫游器 ），由海量计算机集群并行运行
  - 渲染 指下载页面内容后，使用 最新版 Chrome 内核 渲染页面，并执行其中的 JavaScript 代码，此过程与浏览器渲染用户访问的网页的方式类似
- 抓取
  - 抓取策略与限速机制
    - 算法决策：Googlebot 通过算法自动决定 要抓取的网站、抓取频率、从每个网站抓取的网页数量
    - 自适应限速：为避免对服务器造成过大压力，抓取速度会根据网站响应状态动态调整。例如，若网站返回 HTTP 500 错误，Googlebot 会 自动降低抓取频率，以保护服务器稳定性
  - 抓取范围限制，例如以下情况将被跳过抓取
    - 网站通过 robots.txt 明确禁止抓取的路径
    - 需要登录认证或权限验证才能访问的页面
      - 搜索引擎在绝大多数情况下，都是以未登录的匿名用户身份来抓取和渲染页面的
      - 就像是一个第一次访问网站、没有携带任何登录 Cookie 或会话信息的全新浏览器
      - 因此搜索引擎无法索引登录后内容，也不会将它们纳入排名考量，因为它们无法代表普通匿名用户的访问体验
- 渲染
  - 许多现代网站依赖 JavaScript 动态加载主要内容，若跳过渲染，Google 将无法看到页面真实内容，所以搜索引擎不会只看服务器返回的初始 HTML 代码
  - 常见搜索引擎（ Bing，Google，Baidu 等 ）会像一个浏览器一样去渲染整个页面，执行 JavaScript，从而看到最终用户能看到的所有文本、图片和链接
  - 不同搜索引擎的渲染能力和速度存在差异
    - 通常，Google 的渲染能力最强、速度最快；Bing 也在持续跟进；而 百度 虽然已具备 JS 渲染能力，但其处理速度和深度可能相对滞后，因此百度对 JS 网站的收录仍可能存在较大延迟
    - Bing 通过 Bingbot（ 网络抓取机器人 ）建立一个可搜索的索引，而 Bingbot 已采用基于 Chromium 的 Edge 引擎渲染网页（ 与 Google 相同 ），这样网站开发人员对于 seo 兼容性的考虑会少一点
- 抓取与渲染失败的常见原因
  - 服务器问题
    - 网站服务器宕机、响应超时、权限不支持 或 返回 5xx 错误码 等
  - 网络问题
    - DNS 解析故障、网络链路不稳定 等导致无法建立连接
  - 访问限制
    - 网站可能因 robots.txt 文件设置不当、需要登录或 IP 屏蔽等原因，无意中禁止了搜索引擎的访问
    - 同时需要确保可在 无痕式窗口 中访问网站

## 2.3 索引编制

- 索引编制，即 抓取完成后，Google 对网页内容进行 分析 和 存储
- 拿到所有页面内容后，搜索引擎并不是简单地存起来，它会进行复杂的自然语言处理来理解页面主旨与核心信息
  - 基础分析
    - 分析对象：包括处理和分析文字内容以及关键内容标记和属性，例如 `<title>` 元素 和 Alt 属性、图片、视频 等
  - 关键词分析
    - 识别内容的核心主题和关键词
    - 现在的关键词匹配不再是简单的 “出现次数”，而是更注重语义相关性和上下文
  - 实体识别
    - 识别出文本中的人物、地点、事件、产品等具体对象
  - 主题建模
    - 理解整个页面或段落是关于什么主题的
  - 内容质量评估
    - 分析内容的独特性、深度、可读性、是否满足用户搜索意图等
- 去重与规范化
  - 聚类分组：将内容相似或重复的网页归为同一群组（ 即聚类 ）
  - 选择代表网页：从群组中选出一个最具代表性的版本作为，优先在搜索结果中展示
  - 备用版本：群组内的其他网页作为备选，用于特定场景（ 如移动端搜索、精确匹配需求 ）
- 信号收集
  - 为后续的排名阶段准备基础数据，收集的信号包括
    - 网页语言
    - 内容所针对的国家/地区
    - 页面易用性表现
- 所收集的关于规范网页及其网页群组的相关信息会存储在 Google 索引，一个部署在数千台计算机上的大型数据库
- 索引编制失败的常见原因
  - 内容质量低
    - 信息匮乏、无实质价值或大量重复堆砌
  - Robots Meta 限制
    - 页面代码中包含 `<meta name="robots" content="noindex">` 指令，明确禁止索引
  - 网站设计存在技术障碍
    - 如果网站是基于其他一些专业技术（ 而非 HTML ）构建，或者技术结构复杂（ 如过度依赖前端渲染、导航层级过深 ），可能导致爬虫难以完成内容提取
    - 因此如果网站主要依赖图片或视频来传递信息，而缺乏可供抓取的文字内容，搜索引擎也难以理解网站主题

# 2. 检测是否被录入

- `site:` 搜索运算符
  - `site:` 查询是一个搜索运算符，可以使用它请求来自运算符中指定的特定网域、网址或网址前缀的搜索结果
- 示例
  - `site:example.com`
    - 返回已编入索引并呈现给用户的网址的列表，仅显示来自 `example.com` 网域（ `www.example.com` 和 `recipes.example.com` ）的结果
  - `site:example.com/ramen 关键词`
    - 显示包含以 `example.com/ramen` 开头的网址并与 关键词 相关的网页的结果
  - `site:example.com/recipes/tsukemen.html`
    - 可帮助了解特定网址是否已编入索引并呈现给用户
  - `site:example.com viagra casino`
    - 有助于发现和监控网站上的垃圾内容问题，查找网站内是否被黑客注入了违禁词（ 如 赌博、药品 等 ）
- 细节
  - 如果不含查询的关键词，例如 `site:example.com`
    - 系统不会对结果进行排名
    - 系统通常会在顶部显示带有该前缀的最短网址，但除此之外则会相对随机地显示结果
  - 是否返回所有网站
    - 运算符不一定会返回按照查询中指定的前缀编入索引的所有网址
    - 所以如果想确定有多少网址已按照某个前缀编入索引并呈现给用户，`site:example.com` 不太适用

# 3. 加速搜索引擎录入

- 使用官方站长工具（ 最快、最直接的方法 ）
  - 这是加速收录最重要的一步，它为您提供了与搜索引擎直接沟通的官方渠道
  - 站长工具使用前必须注册并验证目标网站的所有权，例如 Goole 的 Google Search Console，Bing 的 Bing Webmaster Tools，百度的 百度搜索资源平台
  - 关键操作
    - 提交网站地图（ sitemap.xml 文件 ），方便用户和蜘蛛一览全站结构
    - 通过 “网址检查”，提交单个 URL 请求索引
    - 监控抓取信息
      - 在站长工具中，可以查看蜘蛛抓取您网站时是否遇到了错误（ 如 404、服务器错误等 ），并及时修复，确保抓取渠道畅通
- 获取高质量外部链接（ 自然引导 ）
  - 搜索引擎蜘蛛沿着链接在互联网上 “爬行”
  - 原理：从其他已被收录且受信任的网站指向新网站的链接，就像是为蜘蛛搭建了一座通往新网站的 “桥梁”
  - 方法
    - 在相关的行业论坛、博客评论区（ 需有价值，非垃圾评论 ）中留下网站的链接
    - 在社交媒体（ 如 LinkedIn, Twitter, 知乎，豆瓣小组等 ）上分享内容
    - 与其他站长进行友情链接交换
  - 注意：质量远大于数量，一个来自权威网站的链接，胜过几十个低质量链接
- 优化内部链接结构（ 内部引导 ）
  - 确保网站内部的链接网络清晰、通畅，让蜘蛛能够轻松遍历所有页面
  - 创建清晰的导航菜单和面包屑导航
  - 在文章内容中，通过上下文锚文本自然地链接到网站内的其他相关页面
- 创建并优化 robots.txt 文件
  - 作用：这个文件位于网站的根目录（ 如 `yourdomain.com/robots.txt` ），用于告诉搜索引擎蜘蛛哪些目录或文件可以或不可以抓取
  - 注意不要错误地使用 `Disallow:` 指令屏蔽了希望被收录的重要资源（ 如 CSS、JS 文件或内容页面 ），否则会严重影响蜘蛛的理解和收录
